## 1. 本次完成内容

### 1.1 通用页面扫描器

新增：

`src/scrollable-page-scanner.mjs`

统一实现标签入口页和标签内容页使用的分步扫描状态机：

1. 初始页面先观察一次。
2. 手指从下向上执行长滑。
3. 每次滑动完成后重新读取 UI hierarchy。
4. 连续3次“可见文字＋文字坐标”不变才确认页面底部。
5. 到底后改为手指从上向下长滑。
6. 连续3次页面签名不变才确认回到顶部。
7. 每个方向最多滑动30次，达到上限后返回明确的扫描异常。
8. 支持在目标出现时立即停止，不继续滑动。

这里的“到底、回顶”均为分步长滑并逐屏检查，不是一次 fling 或瞬间跳转。

### 1.2 标签入口扫描

更新：

`scripts/run-app-screenshot-plan.mjs`

标签入口页当前规则：

1. 初始屏先检查目标标签。
2. 分步向下扫描，每次滑动后检查目标标签。
3. 找到目标标签立即停止。
4. 确认底部后分步回顶，回顶过程中继续检查。
5. 完成一次“到底→回顶”仍未找到才报找不到标签。
6. 标签名称使用 NFKC、空格和英文字母大小写标准化后的完整匹配，不使用包含匹配。

### 1.3 标签内容页扫描

标签内容页当前规则：

1. 进入标签后先观察首屏模型卡片名称。
2. 每次分步滑动后重新采集当前屏模型名称。
3. 如果任务只包含应存在模型，并且全部目标模型已找到，立即停止。
4. 如果包含应删除模型，不允许提前停止，必须完成页面往返后再判断。
5. 扫描证据只用于标签模型名称判断，不额外生成规定截图。
6. 标签任务仍严格保留：
   - 点击标签前：`1/2截图`
   - 进入标签后：`2/2截图`
7. 不再产生 `3of2`、`4of2` 等额外截图。

### 1.4 UI hierarchy 稳定性

当前读取顺序：

1. 优先通过 `uiautomator dump /dev/tty` 直接读取。
2. 失败后写入带当前进程 ID 的临时设备文件并读取。
3. 最多重试3轮。
4. 三轮均失败时返回明确执行异常。

### 1.5 Effects 标签入口

Video 和 Filter 入口拆分为确定步骤：

1. 点击底部 `Effects`。
2. 等待页面稳定。
3. 点击顶部 `Video` 或 `Filter`。
4. 校验当前模块后才开始查找标签。

## 5. 剩余风险

### 5.1 真机覆盖不足

尚未真机验证：

- 到底后回顶途中才找到标签
- 完整往返仍找不到标签
- More Style Video 标签
- More Style AI Filter 标签
- New 标签
- 包含应删除模型的完整扫描

### 5.2 扫描上限

文档描述扫描不设置总时长；当前实现为了防止无限循环，每个方向最多30次滑动。极长页面可能在边界尚未确认前触发安全上限。

### 5.3 动态页面签名

倒计时、动态文字或布局持续变化时，可能无法累计连续3次相同签名。当前会安全失败并进入重试，不会把不完整扫描误报为通过。

### 5.4 UI 与视觉识别

仍依赖：

- Android UIAutomator
- 页面是否暴露可读文字
- 视觉模型对卡片标题的识别
- 网络与模型接口稳定性

文字被截断、UI 不暴露文本或视觉识别波动仍可能造成漏识别。

### 5.5 自动判断范围

标签页当前只核对目标模型名称，不判断：

- 模型排序是否正确
- 标签组封面是否正确
- 模型图片是否为发布目标素材
- 未声明模型是否应该存在

### 5.6 设备适配

滑动坐标按当前测试设备设置。更换分辨率、屏幕方向、系统缩放或导航栏模式后需要重新验证。
