# AM巡检自动化截图系统——自动化测试文档

**版本：** v1.1  
**编制日期：** 2026-07-24  
**适用产品：** AIMirror Android  
**当前阶段：** 第二阶段——发布配置驱动的实体手机截图与模版自动判断  
**文档用途：** 作为产品规则、自动化开发、测试验收以及其他 AI 接续实现的统一依据。

---

## 1. 文档结论

系统读取正式群中的 `AIMirror首屏配置发布成功!` 通知，根据通知里实际出现的配置模块和配置对象，动态生成实体 Android 手机截图任务。

第二阶段只负责：

1. 接收并解析发布通知。
2. 拆分、合并本次发布涉及的截图对象。
3. 自动唤醒手机并打开 AIMirror。
4. 按模块进入对应页面。
5. 等待页面图片加载并按固定节点截图。
6. 给每张截图标注发布配置模块、配置对象和截图序号。
7. 对“模版修改”执行模型名称与图片加载自动判断。
8. 把本次发布的所有模块拼成一张总图。
9. 当前仅把总图发送到测试群。

第二阶段的判断边界：

- 仅“模版修改”自动输出通过、不通过或执行异常。
- 新首页配置、More Style Video配置和More Style AI Filter配置仍然只截图，不判断排序、组封面和模型集合是否正确。
- 当前只判断搜索结果中的模型名称是否匹配、对应模型图片是否正常加载；没有后端预期图片URL或哈希时，不判断图片是否为发布的目标素材。
- 执行国际化配置和新手引导页配置的手机截图。
- 在完整链路验收之前向正式群发送任何测试消息、状态消息或截图报告。

`截图未完成` 只表示自动化执行没有取得规定截图，不代表发布配置错误。

## 3. 系统边界和群聊规则

### 3.1 正式群

- 正式群是发布通知的只读来源。
- 只识别正文以 `AIMirror首屏配置发布成功!` 或 `AIMirror首屏配置发布成功！` 开头的消息。
- 当前由历史消息轮询器每小时读取一次；轮询器启动后立即执行一次读取。
- 使用飞书 `message_id` 持久化去重，同一条发布通知只能生成一次自动化任务。
- 正式群输出实行底层硬白名单：只允许发送标题严格为 `AIMirror首屏配置发布自动化检测报告！` 的最终图片报告。任何文字、状态、异常、测试或临时总结均不得发送到正式群。

### 3.2 测试群

- 测试群可以接收联调和异常信息；正式群只允许接收上述唯一白名单图片报告。
- 启动前必须确认测试群 ID 与正式群 ID 不相同。
- 开发、联调、异常报告、测试截图和状态通知都只能进入测试群。

## 4. 端到端处理流程

1. 轮询器读取正式群最近消息。
2. 找到以 `AIMirror首屏配置发布成功!` 开头的发布通知。
3. 按飞书 `message_id` 去重。
4. 解析操作人、发布环境、配置模块和具体变更行。
5. 只接受当前规定的 `DEV → PRO` 正式发布通知。
6. 把六类发布配置映射为四类APP截图模块和两类人工审核模块。
7. 按“模块＋配置对象”合并重复变更，生成截图任务清单。
8. 为本次没有出现的APP截图模块生成“本次无修改”展示项。
9. 检查USB Android设备状态，唤醒手机并启动 AIMirror。
10. 按任务清单依次执行模型搜索、首页标签、Video标签和Filter标签截图。
11. 单个任务遇到页面找不到或图片加载超时，重启APP并从该任务流程开头重跑。
12. 给每张图片添加统一标题。
13. 把四类APP截图模块拼成一张总图。
14. 将总图发送到测试群并保存本地执行记录。

整体数据流：

```text
正式群发布通知
  → message_id 去重
  → 发布内容解析
  → 配置模块路由
  → 配置对象合并
  → 手机截图任务
  → 异常重试
  → 截图标题
  → 单张总图
  → 测试群
```

## 5. 发布通知结构

标准发布消息由以下内容组成：

```text
AIMirror首屏配置发布成功!
模版修改: ...
More Style AI Filter配置: ...
国际化配置: ...
新首页配置: ...
More Style Video配置: ...
新手引导页配置: ...
操作人: user@riverolls.com
发布环境: 从DEV发布到PRO
```

配置模块不一定全部出现。系统必须以本次消息的真实内容为准，不能把模型名、模型ID、标签名或变更数量写死在脚本中。

### 5.1 六类发布配置

| 序号 | 发布配置模块 | 常见变更内容 | 是否生成APP任务 |
|---:|---|---|---|
| 1 | 模版修改 | 新增/删除模型、模型图片、封面图系列、模型字段 | 是 |
| 2 | More Style AI Filter配置 | 标签模型排序、模型增删、组封面 | 是 |
| 3 | 国际化配置 | 国际化模型新增、删除和语言配置 | 否 |
| 4 | 新首页配置 | 标签模型排序、模型增删、组封面 | 是 |
| 5 | More Style Video配置 | 标签模型排序、模型增删、组封面 | 是 |
| 6 | 新手引导页配置 | 引导页新增、删除、修改和排序 | 否 |

### 5.2 人工审核模块

以下两个模块由人工直接审核：

- 国际化配置
- 新手引导页配置

自动化仍可在内部解析和保存原始消息，但必须遵守：

- 不生成手机截图任务；
- 不占用截图数量；
- 不在最终截图总图中显示；
- 不显示“本次无修改”；
- 不输出任何判断结论。

## 6. 发布配置到截图任务的映射

最终截图总图只包含以下四个APP自动化模块：

1. 模版修改
2. 新首页配置
3. More Style Video配置
4. More Style AI Filter配置

| 模块 | 截图对象 | 合并键 | 单个对象规定截图数 |
|---|---|---|---:|
| 模版修改 | 模型名称 | 模块＋模型名称 | 1 |
| 新首页配置（普通标签） | 标签名称 | 模块＋标签名称 | 2 |
| 新首页配置（New） | `New` | 模块＋`New` | 4 |
| More Style Video配置 | 标签名称 | 模块＋标签名称 | 2 |
| More Style AI Filter配置 | 标签名称 | 模块＋标签名称 | 2 |

### 6.1 动态任务原则

- 模型名称来自发布消息，不写死。
- 标签名称来自发布消息，不写死。
- 模型ID作为发布变更的附加信息保存，不为每个ID单独生成截图。
- 同名标签出现在不同模块时必须分别生成任务。
- 同一对象在一条消息中重复出现时只生成一个任务。
- 截图对象顺序默认保持其在发布消息中第一次出现的顺序。

### 6.2 合并规则

#### 模版修改

同一个模型同时出现以下多种变化时，合并为一个模型截图任务：

- 新增模型；
- 删除模型；
- 模型图片改变；
- 模型封面图系列改变；
- 模型字段改动。

示例：

```text
模型Farewell Paw图片改变
模型Farewell Paw的封面图系列有改动
模型Farewell Paw有字段改动
```

只生成：

```text
模版修改｜Farewell Paw｜1/1截图
```

#### 标签类配置

同一模块、同一标签同时出现以下变化时，合并为一个标签截图任务：

- 标签模型排序改变；
- 新增模型；
- 删除模型；
- 标签组封面修改。

示例：

```text
标签Baby的模型排序改变
新增了模型(所属标签Baby)[980]
标签Baby的组封面修改
```

只生成一个 `Baby` 标签任务，共2张截图。

## 7. 统一截图标题规则

每一张正常截图必须使用以下标题：

```text
发布配置模块｜配置对象｜当前截图序号/该对象截图总数截图
```

强制示例：

```text
模版修改｜Tiny Cleaner｜1/1截图
新首页配置｜Best Companion｜1/2截图
新首页配置｜New｜3/4截图
More Style Video配置｜Seedance 2.0｜2/2截图
More Style AI Filter配置｜Baby｜2/2截图
```

约束：

- 模块名称必须使用发布消息中的标准名称。
- 配置对象只能填写模型名或标签名。
- 序号按单个配置对象独立计算。
- 标题必须直接显示在图片上方或下方，不能只写在文件名中。
- 拼接总图后仍必须能清楚读取每张图的完整标题。
- “模版修改”允许并要求显示 `通过`、`不通过` 或 `执行异常`；其他三个APP模块不得显示业务判断。

异常现场截图使用：

```text
发布配置模块｜配置对象｜当前已取得截图数/规定截图总数截图｜截图未完成
```

如果一张规定截图都没有取得：

```text
新首页配置｜Best Companion｜0/4截图｜截图未完成
```

`截图未完成` 只描述执行状态。

## 8. 模版修改截图流程

### 8.1 适用变更

- 新增模型；
- 删除模型；
- 模型图片改变；
- 模型封面图系列改变；
- 模型字段改动。

### 8.2 正常流程与自动判定

1. 启动或恢复 AIMirror 首页。
2. 点击首页右上方的搜索图标。
3. 输入发布消息中的完整模型名称并点击 `Search`。
4. 保持第一张搜索结果卡片完整可见，不打开卡片。
5. 读取第一张结果卡片的模型文字、图片状态和页面错误状态；搜索输入框中的文字不能作为结果卡片证据。
6. 对模型名称执行 Unicode NFKC、首尾空格、连续空格和英文字母大小写标准化后完整匹配，不使用模糊名称自动通过。
7. 检查同一张结果卡片内的图片不是空白、灰色占位图、骨架屏或加载动画。
8. 截取搜索结果页面1张，并把判定、原因和证据写入执行结果。
9. 标题格式：`模版修改｜模型名称｜1/1截图｜通过/不通过/执行异常`。

非删除模型只有同时满足“第一张卡片名称完整匹配”和“该卡片图片正常加载”才判定通过；没有对应文字、名称不一致、无搜索结果或图片异常均判定不通过。网络错误、APP错误、设备错误和AI读取失败单列为执行异常。

### 8.3 同一模型多种变化

一个模型无论同时出现多少种修改，只搜索一次、截图一次。

### 8.4 删除模型反向判定

当发布消息明确表示 `删除模型: 模型名称` 时：

1. 仍然按照完整模型名称执行搜索。
2. 页面明确显示无搜索结果时，判定通过并截图。
3. 第一张结果卡片仍显示对应模型名称时，判定不通过并截图。
4. 搜索页出现无关结果但没有明确“无结果”证据时，不自动认定删除成功，判定不通过。
5. 网络、APP或设备异常时标记执行异常。
6. 不通过或执行异常时重启APP并重跑当前模型，自动重试2次。

标题格式：

```text
模版修改｜模型名称｜1/1截图｜通过/不通过/执行异常
```

## 9. 新首页配置截图流程

### 9.1 普通标签

适用于除 `New` 之外的新首页标签。

步骤：

1. 启动或恢复 AIMirror 首页。
2. 先用手指从屏幕下方向上方长滑，查找发布消息中的标签名称。
3. 滑动查询不设置总时长；每次滑动后读取界面文字，连续3次滑动后文字均无变化时认定到达底部。
4. 到达底部后改为手指从屏幕上方向下方长滑；连续3次文字均无变化时认定回到顶部，一组完整滑动查询结束。
5. 查询过程中找到目标标签就立即停止滑动；完整往返后仍未找到，才按“找不到目标标签”处理。
6. 找到标签后等待图片加载，最长等待2分钟。
7. 图片出现后，在点击标签前截图，记为 `1/2截图`。
8. 点击标签文字进入标签内容页，截图，记为 `2/2截图`。



示例：

```text
新首页配置｜Best Companion｜1/2截图
新首页配置｜Best Companion｜2/2截图


```

### 9.2 New标签特殊流程

`New` 不执行普通标签流程。

步骤：

1. 启动或恢复 AIMirror 首页。
2. 在 `Inspiration` 下方找到左侧第一张带有 `New` 标识的卡片。
3. 点击卡片进入内容页。
4. 进入页面后连续滑动并取得4张截图。
5. 首页入口卡片不计入这4张截图。

标题依次为：

```text
新首页配置｜New｜1/4截图
新首页配置｜New｜2/4截图
新首页配置｜New｜3/4截图
新首页配置｜New｜4/4截图
```

## 13. 页面查找、图片等待和重试规则

### 13.1 滑动查询边界

1. 滑动查询过程不设置总时长限制。
2. 第一阶段固定执行手指“下→上”的长滑，每次滑动后读取当前界面文字。
3. 连续3次“下→上”滑动后界面文字均无变化，认定已经到达页面底部。
4. 到达底部后固定改为手指“上→下”的长滑。
5. 连续3次“上→下”滑动后界面文字均无变化，认定已经回到页面顶部。
6. 到达顶部后，一组完整滑动查询结束。
7. 任一方向滑动过程中识别到目标标题，立即停止边界扫描并进入截图流程。
8. 完成“顶部→底部→顶部”往返仍未找到目标，才判定本次尝试找不到目标标签。

### 13.2 可触发重试的情况

- 按规定步骤找不到目标页面；
- 找不到目标标签；
- APP停留在异常页面；
- APP闪退或无响应；
- 非删除模型场景中找不到可截图的目标内容；
- 页面图片连续2分钟没有完成加载。

### 13.3 重试动作

1. 结束当前任务尝试。
2. 重启 AIMirror。
3. 恢复到首页。
4. 从当前配置对象的完整流程开头重新执行。

重试的是当前配置对象任务，不重复创建发布任务，也不重复处理 `message_id`。

### 13.4 次数

- 首次执行：1次；
- 自动重试：2次；
- 单个配置对象最多执行：3次。

### 13.5 最终仍未取得规定截图

第三次执行仍未完成时：

1. 停止该配置对象继续重试；
2. 保留最后一次异常现场截图；
3. 使用 `截图未完成` 标题；
4. 继续处理本次发布中的下一个配置对象；
5. 总图中保留该异常现场，不能静默删除。

### 13.6 不触发重试的特殊情况

发布消息明确表示删除模型，并且搜索页面显示无结果时，这是规定的正常截图场景，不触发重试。

## 14. 总图生成规则

### 14.1 总图范围

一次发布只生成一张截图总图。总图包含：

- 发布消息ID；
- 操作人；
- 发布环境；
- 发布时间或消息时间；
- 四类APP截图模块；
- 所有配置对象截图；
- 未修改模块文字；
- 最终未完成任务的异常现场截图。

### 14.2 排列顺序

模块采用固定顺序：

1. 模版修改
2. 新首页配置
3. More Style Video配置
4. More Style AI Filter配置

模块内按照配置对象在发布消息中第一次出现的顺序排列；同一对象的截图按 `1/N` 到 `N/N` 排列。

### 14.3 图面要求

- 所有模块必须拼在同一张总图中。
- 每张手机截图比例保持一致。
- 标题文字必须清楚、完整。
- 不得因为拼图而裁掉关键页面内容。
- “本次无修改”作为该模块的文字块显示。
- 不显示国际化配置和新手引导页配置。
- “模版修改”显示自动判定结论；其他配置模块不显示业务通过或失败结论。

## 20. 最终规则清单

1. 发布消息是截图任务的唯一业务输入。
2. 使用飞书 `message_id` 去重。
3. 模型、模型ID和标签都来自消息，不能完全写死。
4. 四类模块执行APP截图。

6. 同一模型的多种修改合并成一个1张截图任务。
7. 同一模块、同一普通标签的多种修改合并成一个2张截图任务。

11. 图片最多等待2分钟。
12. 找不到页面或图片超时后重启APP，从当前任务开头重跑。
13. 首次执行之外自动重试2次，单任务最多3次。

17. 一次发布的所有模块拼成一张总图。
18. APP自动化仅对“模版修改”判断模型名称和图片加载状态；其他模块只负责截图。

## 21. 模版修改自动判定数据规则

### 21.1 任务输入

每个模版模型任务至少包含：

- `objectName`：发布消息中的模型名称；
- `changeTypes`：新增、删除、图片、封面系列或字段变更；
- `expectedState`：`PRESENT`、`ABSENT` 或 `CONFLICT`；
- `businessVerdictEnabled`：固定为 `true`。

只有纯删除任务使用 `ABSENT`；新增、图片、封面系列和字段变更使用 `PRESENT`；同一模型同时包含删除与非删除变更时使用 `CONFLICT` 并标记执行异常，交人工确认。

### 21.2 页面证据

每次尝试必须记录：

- `resultState`：`RESULTS`、`NO_RESULTS`、`LOADING`、`NETWORK_ERROR`、`APP_ERROR` 或 `UNKNOWN`；
- `firstResultVisible`：第一张实际结果卡片是否可见；
- `firstResultTitle`：第一张结果卡片的可见模型名称，不得读取搜索输入框文字代替；
- `firstResultImageState`：`LOADED`、`PLACEHOLDER`、`LOADING`、`MISSING` 或 `UNKNOWN`；
- `uiTexts`：Android UI层可读取的页面文字；
- `extractedAt`：证据读取时间。

### 21.3 输出状态

- `PASS`：满足该任务的存在或删除预期；
- `FAIL`：页面可正常读取，但模型名称、搜索结果或图片状态不符合预期；
- `ERROR`：网络、APP、设备、AI读取失败或变更声明冲突；
- `NOT_EVALUATED`：新首页、Video和Filter等只截图模块。

### 21.4 主要原因码

| 原因码 | 含义 |
|---|---|
| `MODEL_TEXT_AND_IMAGE_MATCH` | 名称完整匹配且图片正常加载 |
| `MODEL_NOT_FOUND` | 应存在的模型搜索无结果 |
| `MODEL_TEXT_MISSING` | 第一张结果卡片没有模型文字 |
| `MODEL_TEXT_MISMATCH` | 第一张结果名称与发布模型不一致 |
| `MODEL_IMAGE_NOT_LOADED` | 对应卡片图片缺失、占位或仍在加载 |
| `DELETED_MODEL_NOT_FOUND` | 删除模型搜索无结果，符合预期 |
| `DELETED_MODEL_STILL_VISIBLE` | 删除模型仍能搜索到对应名称 |
| `DELETION_NOT_PROVEN` | 没有明确无结果证据，不能确认删除成功 |
| `SEARCH_PAGE_ERROR` | 搜索页出现网络或APP错误 |
| `AUTOMATION_EXECUTION_ERROR` | 手机自动化未能完成 |

### 21.5 重试与报告

1. 图片或页面最长等待2分钟。
2. 首次不通过或执行异常后重启APP，从当前模型搜索开头重跑。
3. 自动重试2次，最多执行3轮。
4. 最终一轮仍不通过时，保留该轮截图并在总图标记不通过及原因。
5. 三轮都无法完成截图时标记 `截图未完成` 和执行异常。
6. 总图顶部统计模版修改的通过、不通过和执行异常数量；其他模块仍只展示截图。
7. 当前报告只发送测试群，正式群继续禁用。
